查询前处理：safety / intent / rewrite

本课目标：你能解释为什么查询链路第一步是 safety_guard，以及 QueryService.prepare() 做了什么。

Tangible win：能用一句话说明“安全 → 意图 → 术语扩展 → 改写 → 过滤”的顺序。

1. 查询前处理流水线

query API
  → safety_guard（攻击性请求识别）
  → intent_classifier（意图分类）
  → term_expander（术语扩展）
  → query_rewriter（改写）
  → metadata_filter_builder（过滤）

2. 各模块职责

safety_guard

识别攻击性请求，输出 allow / refuse / redirect。

intent_classifier

识别用户意图：法规、标准、教材、概念解释、漏洞修复、攻击请求等。

term_expander

扩展术语词典，例如“等保”→“等级保护”。

query_rewriter

生成 rewritten_query、search_keywords、sub_queries。

3. 为什么顺序不能乱？

  • 安全必须先于检索，否则攻击请求会污染检索结果。
  • 意图分类影响 filter 和 rewrite 策略。
  • 术语扩展提高召回率。

4. 练习

  1. “绕过 WAF 的 SQL 注入 payload”会走哪条路径？
  2. “等保三级日志要留多久”会识别为哪种意图？
  3. 为什么 QueryService.prepare() 不直接调 answer_generator？
展开参考答案
  1. safety_guard 会 refuse 或 redirect，不会进入检索。
  2. standard_query（标准条款查询）。
  3. prepare 只做前处理；answer 是另一条链路，由 answer() 调用。
