评测体系：golden dataset 与指标

本课目标：你能解释“为什么评测必须持久化”，以及 Recall@K / MRR / citation / refusal 各自衡量什么。

Tangible win：能一句话说清“golden dataset → 真实 query 链路 → 指标 → eval_runs 持久化”。

1. 评测流水线

eval/golden_dataset.jsonl
  → eval_service 物化 dataset / items
  → 对每条样本跑真实 query 链路
  → 计算指标
  → 写入 eval_runs / eval_run_items
  → 返回 run summary

2. 核心指标

Recall@K

目标 chunk 是否出现在 top K 中。

MRR

目标 chunk 首次出现的位置质量（倒数排名）。

Citation Accuracy

答案引用是否被证据支持。

Refusal Accuracy

该拒答的问题是否真的触发拒答。

3. 为什么必须持久化？

  • 日志只适合一次性观察，不能稳定比较“这次改动后 Recall@K 是上升还是下降”。
  • 评测要成为工程能力，就必须沉淀到 eval_runs / eval_run_items。

4. 练习

  1. 为什么 refusal accuracy 要单独统计？
  2. citation accuracy 能等价于 answer quality 吗？
  3. 你改了 retrieval top_k，应该如何验证效果？
展开参考答案
  1. 安全领域 RAG 不能只看“答得准不准”，还要看“不该答的时候有没有拒答”。
  2. 不能。它衡量 groundedness 的最低门槛；答案质量还涉及表达、覆盖度与完整性。
  3. 跑一次 /eval/run，对比前后 Recall@K / MRR。
