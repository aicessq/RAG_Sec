混合检索与 RRF 融合

本课目标：你能解释为什么“向量 + FTS + RRF”优于单一方式，以及 reranker 的位置。

Tangible win：能一句话说清“top_k=30 + k=60 + rerank top 20 + evidence top 5”的含义。

1. 检索流水线

query
  → 向量搜索（Qdrant, top_k=30, Cosine）
  → 关键词搜索（FTS, top_k=30，可 fallback ILIKE）
  → 并入候选
  → RRF 融合（k=60）
  → reranker 重排（top 20 → 1 号）
  → evidence top 5
  → parent context 回取

2. RRF 是什么

Reciprocal Rank Fusion：按排名倒数融合多路结果，不受向量相似度量纲影响。

3. 为什么 reranker 在融合后？

  • 先用向量/FTS 召回候选（高效）。
  • 再用真实 reranker 对融合后 top 20 做重排（精准度更高）。
  • 避免把 reranker 当初筛（太慢）。

4. 练习

  1. 如果用户查询“等保”，向量召回可能差，FTS 召回可能好，应该怎么融合？
  2. 为什么证据最终只取 top 5？
  3. 你看到一个 chunk 的 score 很高，却被 reranker 降到 20 以下，这是正常现象吗？
展开参考答案
  1. 先并入候选，再融合（RRF）。
  2. 减少幻觉和 prompt 超长；答案生成时会挑最相关的。
  3. 正常；reranker 学习了相关性分布，可能比纯向量更准。
