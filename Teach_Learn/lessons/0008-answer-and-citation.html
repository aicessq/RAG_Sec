答案生成与引用校验

本课目标：你能解释“证据如何变成带 citation 的回答”，以及 citation_checker 的作用。

Tangible win：能用一句话说明“answer_generator 生成答案，citation_checker 校验引用是否被证据支持”。

1. 答案生成流水线

evidence top 5
  → parent context 回取
  → answer_generator（LLM）
  → citation_checker（校验）
  → query_log 持久化
  → 返回 answer + citations

2. 为什么需要 citation_checker？

  • 答案可能编造法规条款、标准编号、页码。
  • checker 检查关键结论是否被检索证据支持。
  • 不支持的 claim 会被修正或标记。

3. 引用最小粒度

  • 必须返回：chunk_id、doc_title、page_start、page_end
  • 若有 chapter / section / article_no，则必须返回
  • 不允许伪造条款号或章节号

4. 练习

  1. 如果 answer_generator 生成了“第 21 条”，但证据里没有，会发生什么？
  2. 为什么 parent context 要回取？
  3. 你看到一个 citation 的 page_start 是 null，这是什么情况？
展开参考答案
  1. citation_checker 会标记 unsupported_claims，并修正答案。
  2. child 太短，parent 提供更完整上下文，减少幻觉。
  3. 证据没有页码信息；可能是教材或 Markdown 文档。
