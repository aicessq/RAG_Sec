Parent-Child Chunk 与“只索引 child”

本课目标：你能解释为什么 parent_chunk_id 是自引用、child 为什么进向量/FTS，而 parent 为什么只存库。

Tangible win：能一句话解释“child 检索，parent 上下文”——以及检索默认过滤的四重可见性。

1. 为什么要 parent-child？

  • 检索需要短、规范的文本片段（child）。
  • 生成答案需要长上下文（parent），不能每次都把整文档塞进 prompt。
  • child 进 Qdrant、FTS；parent 只存 PostgreSQL。

2. 模型关系

chunks
├─ child（chunk_type=child, is_active=true）
└─ parent（chunk_type=parent, is_active=true）
   └─ parent_chunk_id → self

3. 检索可见性（必须同时满足）

  1. documents.status = active
  2. document_versions.version_status = active
  3. 版本是该 document 的 current_version_id
  4. chunks.is_active = true 且 chunk_type = child

4. 练习

  1. 检索时为什么不会命中 parent？
  2. 替换文档时，为什么 child chunk 仍要落新 DB 行（即使向量复用）？
  3. 你看到一个 chunk 没有 parent_chunk_id，这是什么情况？
展开参考答案
  1. 查询只查 chunk_type=child。
  2. unchanged child 必须保留新版本记录（避免脏读），但向量可复用。
  3. 是孤儿 chunk；可能是早期版本或手动清理。
