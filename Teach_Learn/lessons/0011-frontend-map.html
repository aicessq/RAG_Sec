前端 MVP 如何对接后端

本课目标：你能把 frontend/ 里的页面和后端 API 一一对应起来，并知道改 UI 时该先动哪边。

Tangible win：能说出 Dashboard / Upload / Retrieve / Rewrite / Answer / Eval 各自调用的接口前缀。

1. 前端是什么

  • 独立 React + TypeScript + Vite MVP，不是规格第一版必做项，但是仓库里已有的演示层。
  • 通过 VITE_API_BASE_URL（默认 http://localhost:8000）调用 FastAPI。
  • 脚本只有 dev / build / preview，没有单独的前端测试或 lint 脚本。

2. 页面 ↔ API 对照

Upload

POST /api/v1/documents/upload，再轮询任务状态。

Retrieve

POST /api/v1/query/retrieve，调试混合检索结果。

Rewrite

POST /api/v1/query/rewrite，看 intent / 改写 / filter。

Answer

POST /api/v1/query/answer，完整问答链路。

Eval

POST /api/v1/eval/run，跑 golden dataset。

Dashboard

聚合入口与状态概览，不承载核心业务逻辑。

3. 读前端的方法

frontend/
  → 路由/页面组件（用户动作入口）
  → API client / fetch 封装（看 base URL 与路径）
  → 对照 backend/app/api/*.py 与 schemas
  → 业务对错仍以 backend services 为准

前端不实现 RAG 逻辑；它只是驱动已有 API。修“答错了 / 检索差”应回到 backend，而不是在 React 里补业务。

4. 练习

  1. Answer 页超时，你先查前端还是 query_service / worker？
  2. 想在 UI 显示 rewritten_query，但 API 响应没有该字段，该改哪三处？
  3. npm run build 实际做了哪两步？
展开参考答案
  1. 先确认网络与 API 是否通；业务超时/逻辑问题看 backend 的 answer 链路，不在前端“发明”答案。
  2. backend schema + api/query.py 出参（数据来自 service）+ 前端展示字段。
  3. tsc -b 类型检查，再 vite build 打包。
