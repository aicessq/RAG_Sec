用一张地图读懂项目结构

这一课的目标不是记住所有文件，而是学会一个定位方法：从用户动作反推代码入口，再沿着服务层往下走。

你的第一个 tangible win：看见一个功能需求时，你能判断它大概率属于 api/、services/、workers/、models/ 还是 frontend/。

1. 先分清“项目外壳”和“业务核心”

这个仓库不是单一 Python 脚本，而是一个完整应用。外层文件负责运行、配置和文档；核心代码分成后端与前端。

  • README.md：当前实现状态和运行说明。
  • CLAUDE.md：给 AI 助手的项目规则，也是很好的架构导览。
  • Doc/文档2.MD：权威规格；当代码和说明冲突时优先看它。
  • backend/：RAG 安全系统的大部分业务逻辑。
  • frontend/：用户界面，调用后端 API。

2. 后端按“层”读，不按文件名乱翻

项目约定：API 路由保持薄，真正流程放在 service 或 worker。你读代码时可以按下面顺序：

HTTP 请求
  ↓
backend/app/api/*.py          # 找接口入口
  ↓
backend/app/services/*.py     # 找业务流程
  ↓
backend/app/models/*.py       # 找数据库对象
  ↓
外部依赖：PostgreSQL / Redis / Qdrant / LLM

3. 用四条主流程建立骨架

上传 / ingest

看 upload_service、ingest_worker、parser/cleaner/chunk/index 相关服务。

查询 / answer

看 api/query.py，再跟到 safety、intent、rewrite、retrieve、answer、citation。

替换 / update

看 api/documents.py 和 services/update_service.py。

评测 / eval

看 api/eval.py、services/eval_service.py 和 eval/golden_dataset.jsonl。

4. 练习：从需求定位文件

不看答案，先在心里回答：

  1. “上传 PDF 后没有进入后台处理”，你会先看哪两个区域？
  2. “回答引用不准确”，你会先看哪个服务和哪个 prompt？
  3. “替换文档后旧内容还能被检索到”，你会先看哪个 service？
展开参考答案
  1. app/api/upload.py / upload_service.py，再看 workers/ingest_worker.py 与 Celery 配置。
  2. services/citation_checker.py 与 prompts/citation_checker.md，也可能回看 answer_generator。
  3. services/update_service.py，重点看 PostgreSQL、FTS、Qdrant 可见性是否同步。
